BrewQuiverUICore.BrewQuiverUICore — Module
BrewQuiverUICore

The frontend-neutral core of the BrewQuiver user interfaces: an editing Session of a quiver of BrewQuiver, with its file, its brew, the selection and (in later versions) the edit commands, their history with undo and redo, view data and layout. Plain Julia data and functions, shared by the terminal (BrewQuiverTerm) and graphical (BrewQuiverApp) frontends.

Sessions

BrewQuiverUICore.Session — Type
Session(q::Quiver; path = nothing, models = (;))

An editing session of the quiver q, saved at path (or not yet saved), brewed with the models of BrewingFormulas (see brew). It holds:

  • the quiver (quiver) and its file (filepath);
  • its latest brew (result) and the state of the brew (status): Brewed, or BrewFailed when the quiver was loaded in a state that does not brew;
  • the nodes whose results changed in the last step (changed), for interfaces to highlight, and the warnings of the brew;
  • the selection (selection): nodes and arrows;
  • the history of the edits (History), for undo! and redo!;
  • a library of ingredients to add (library, catalog).

After an edit, the brew is updated with rebrew! from the earliest affected nodes, falling back to brew.

See also open_session, import_recipe, save!.

Commands

BrewQuiverUICore.EditCommand — Type
EditCommand

Supertype of the edits of a quiver in a Session, applied with apply!. Each command implements:

  • validate(cmd, q): throws a CommandError if cmd cannot be applied to q, changing nothing;
  • affected(cmd, q): the nodes to rebrew from after it (computed before it);
  • describe(cmd): a short description, e.g. "Set :pale to 4.8 kg";
  • revert_record(cmd, q): what reverts it exactly (computed before it): an Inverse command or a Snapshot of the quiver;
  • brew_effect(cmd): Rebrews or LayoutOnly;
  • perform!(q, cmd) (internal): the change itself.
source
BrewQuiverUICore.CommandError — Type
CommandError(description, message)

A command was refused: description is that of the command, message why. The session is left as it was.

source
BrewQuiverUICore.apply! — Function
apply!(s::Session, cmd::EditCommand)

Applies the edit cmd to the session s:

  1. validates it (validate); BrewQuiver checks the rules of the quiver as it is performed, before changing anything;
  2. records what reverts it (revert_record);
  3. performs it, and updates the brew with rebrew! from the nodes it affected (falling back to brew), unless it only changes the layout (LayoutOnly);
  4. updates the selection (following a renamed node, dropping removed items).

A refused command throws a CommandError and leaves the session as it was. That includes an edit after which a quiver that brewed no longer does (e.g. a drain with not enough liquid): the edit is reverted. A quiver that did not brew (loaded so) can be edited until it does.

Returns what the command gives: the Solution of a Solve, else nothing.

source

validate(cmd::EditCommand, q::Quiver)

History

BrewQuiverUICore.History — Type
History(; limit = 100, merge_window = 1.5, clock = time)

The history of a Session, in memory only: at most limit steps can be undone. Consecutive edits of the same field (the same mergekey) are merged into one step when they come within merge_window seconds of each other, by the clock (a function giving seconds; replaceable in tests).

source
BrewQuiverUICore.undo! — Function
undo!(s::Session)

Undoes the last step: reverts its commands, in reverse order, updates the brew from the nodes they affected, and restores the selection before it. Returns its description, or nothing if there is nothing to undo. Not allowed while a transaction is open.

source
BrewQuiverUICore.redo! — Function
redo!(s::Session)

Redoes the last step undone: applies its commands again, updates the brew, and restores the selection after it. Returns its description, or nothing if there is nothing to redo. Not allowed while a transaction is open.

BrewQuiverUICore.isdirty — Function
isdirty(s::Session)

Whether the session has changes not saved: its state is not the one last saved (or loaded) with its file. Undoing back to the saved state makes it clean again; a session never saved (e.g. an imported recipe) is dirty.

source
BrewQuiverUICore.mergekey — Function
mergekey(cmd::EditCommand)

The key of what cmd sets, for merging consecutive edits into one step of the history (e.g. typing in a number box), or nothing (the default) for commands that are never merged. Two consecutive commands with the same key are merged when the second comes within the merge_window of the History of the first, and no save, undo or redo came between them: the step keeps what reverts the first, and the description of the last. Commands with a key must set the whole of what it names, so that the last one alone redoes the step.

source
BrewQuiverUICore.begin_transaction! — Function
begin_transaction!(s::Session, description)

Opens a transaction: the edits applied until commit! are one step of the history, with description (e.g. "Move 3 nodes", "Paste"). The edits are applied, and the brew updated, as they come (e.g. a node dragged across many frames). Transactions opened inside another one fold into it: only the outermost one makes a step.

See also abort!, transaction.

source
BrewQuiverUICore.commit! — Function
commit!(s::Session)

Closes the transaction opened by begin_transaction!: when it is the outermost one, its edits become one step of the history (none if there were no edits).

source
BrewQuiverUICore.abort! — Function
abort!(s::Session)

Aborts the open transaction, and those it is in: reverts all its edits, restoring the quiver, the brew and the selection as they were when it was opened. Nothing goes into the history.

source
BrewQuiverUICore.transaction — Function
transaction(f, s::Session, description)

Calls f() in a transaction (begin_transaction!): its edits are one step of the history, committed when f returns, or aborted if it throws (the exception is rethrown).

    apply!(s, MoveNode(:mash, [0, 1]))
    apply!(s, MoveNode(:rested, [1, 1]))
end

What a user typed, as a value for an edit command: a quantity ("4.8 kg", "1.050 sg", "95%", "70 min", "4 L/h", "80 °C", "2.4 vols", any unit of Unitful or UnitfulBrewing), a plain number ("2", "0.95"), nothing ("", "-", "–", "nothing", "none": leave it to the vessel or the default), a timing ("10 min remaining", "at 70 min"), or true/false. Layout

BrewQuiverUICore.layout — Function
layout(q::Quiver; sweeps = 8) -> Dict{Symbol, Vector{Float64}}

A layered layout of q: the position [x, y] of each node, in abstract layout units.

  • x is the layer: the length of the longest path from a source to the node, so that every arrow goes from left to right. A lot (a source) is put in the layer just before its first destination, next to where it is used (the hops by the kettle), rather than with all the sources at the start.
  • y is the slot in the layer, 0, 1, 2, ... from the top. The nodes of a layer are ordered by the barycenter of their neighbours in the layers before and after (sweeping sweeps times), to reduce the crossings of the arrows; the nodes of the same vessel in a layer are kept together, and the vessels keep their order.

See layout! to write it into the nodeviews, and positions.

source

Models

BrewQuiverUICore.SetModels — Type
SetModels(models::NamedTuple)

Brews the session with the models of BrewingFormulas (overriding DEFAULT_MODELS; see MODEL_CHOICES), e.g. SetModels((bitterness = Rager(),)). The models are not part of the quiver, but of the session: the whole quiver is brewed again with them. Reverted by its Inverse.

source
BrewQuiverUICore.MODEL_CHOICES — Constant
MODEL_CHOICES

The models of BrewingFormulas a session can brew with, by kind, the first being the default (see DEFAULT_MODELS): bitterness (Tinseth, Rager), color (Morey, Daniels, Mosher, Druey-Daniels, Druey-Noonan), abv (Balling, simple) and gravity (the equivalence between sugar content and specific gravity).
