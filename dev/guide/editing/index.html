Editing, undo and redo

Applying commands

s = Session(single_batch())
apply!(s, SetAmount(:pale, 4.8u"kg"))
apply!(s, SetArrowField(:kettle => :wort, 1, :time, 70u"minute"))
apply!(s, SetArrowField(:cascade, :kettle, 2, :amount, 20u"g"))
[h.description for h in history(s)]
3-element Vector{String}:
 "Set :pale to 4.8 kg"
 "Set the time of :kettle => :wort to 70 minute"
 "Set the amount of :cascade => :kettle #2 to 20 g"

A refused command says why, and changes nothing, the selection included:

for cmd in (Connect(:bottles => :pale), SetArrowField(:kettle, :wort, 1, :time, 3u"kg"),
            RenameNode(:kettle, :wort))
    try
        apply!(s, cmd)
    catch e
        println(sprint(showerror, e))
    end
end
Connect :bottles => :pale: an arrow from :bottles to :pale would create a cycle
Set the time of :kettle => :wort to 3 kg: the time takes a quantity in minute, not 3 kg
Rename :kettle to :wort: there is already a node labelled :wort

Undo and redo

undo_description(s), canredo(s)
("Set the amount of :cascade => :kettle #2 to 20 g", false)
undo!(s); undo!(s)
redo_description(s)
"Set the time of :kettle => :wort to 70 minute"
[(h.done ? "done:   " : "undone: ") * h.description for h in history(s)]
3-element Vector{String}:
 "done:   Set :pale to 4.8 kg"
 "undone: Set the time of :kettle => :wort to 70 minute"
 "undone: Set the amount of :cascade => :kettle #2 to 20 g"

Undo and redo restore the brew, from the nodes the step affected, and the selection of before or after the step. A new edit clears the redo stack.

Transactions

Edits made in a transaction are one step. They are applied, and brewed, as they come, so that an interface shows them live (a node dragged); aborting reverts them all.

transaction(s, "Brew a stronger beer") do
    apply!(s, SetAmount(:pale, 5u"kg"))
    apply!(s, SetAmount(:crystal, 0.4u"kg"))
end
undo_description(s)
"Brew a stronger beer"

begin_transaction!, commit! and abort! do the same in steps, e.g. across the frames of a drag, with Escape to abort. The do-block form aborts when its block throws, including when an edit in it is refused. Transactions opened inside another fold into the outermost; undo and redo are refused while one is open.

Merging

Typing 4.6, 4.7, 4.8 into a number box applies three commands; they make one step, because consecutive commands with the same mergekey (the same aspect of the same item) merge when they come within the merge_window of the History (1.5 s by default) and no save, undo or redo came between them. The step keeps what reverts the first, and the description and command of the last.

s = Session(single_batch())
for m in (4.6, 4.7, 4.8)
    apply!(s, SetAmount(:pale, m * u"kg"))
end
[h.description for h in history(s)]
1-element Vector{String}:
 "Set :pale to 4.8 kg"

The saved marker

file = joinpath(mktempdir(), "bitter.quiver.json")
save!(s, file)
apply!(s, SetAmount(:crystal, 0.4u"kg"))
a = isdirty(s)
undo!(s)
a, isdirty(s)
(true, false)

A session is clean only in the state it was last saved or opened in; when that state can no longer be reached (its step dropped by a new edit, or by the bounded length of the history), it stays dirty until saved. A session never saved, such as an imported recipe, is dirty.

Ingredients

The catalog of a session holds the ingredients that can be added: those of its quiver, those of its library (BeerJSON documents of ingredients, see set_library!), and the salts and acids of WATER_AGENTS. find_ingredient finds one by name, or by a part of it when only one matches.

apply!(s, AddNode(:gypsum, find_ingredient(s, "gyps") => 4u"g"))
apply!(s, Connect(:gypsum => :mash))
format(profile(result(s)[:mash]).sulfate)
"139 mg/L"

Models, inventory and export

The models of BrewingFormulas a session brews with are changed by a command, so that the change can be undone (SetModels, set_model, MODEL_CHOICES):

apply!(s, set_model(s, :bitterness, Rager()))
models_in_use(s).bitterness, format(node_summary(s, :wort).ibu)
(Rager(), "26 IBU")

inventory_rows compares what the brew needs with the stock of the library, consume_stock! takes it from the stock (not undoable: it changes the library, saved with save_library), and export_recipes writes the brew as BeerJSON recipes.

set_library!(s, Library())     # (an empty library: nothing in stock)
[(r.name, r.needed isa Real ? "$(Int(r.needed)) ×" : format(r.needed), r.short ? "short" : "")
 for r in inventory_rows(s)]
5-element Vector{Tuple{String, String, String}}:
 ("Cascade", "50 g", "short")
 ("Corn sugar", "130 g", "short")
 ("Crystal 60", "300 g", "short")
 ("Pale ale malt", "4.80 kg", "short")
 ("US-05", "1 ×", "short")
